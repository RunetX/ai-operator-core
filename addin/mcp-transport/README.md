# MCP-транспорт ИИ-оператора

Внешняя компонента Native API для 1С:Предприятия: сервер MCP Streamable HTTP на `127.0.0.1` с проверкой Bearer-токена. Через неё MCP-клиенты (Claude Code, Claude Desktop, LM Studio) вызывают инструменты ИИ-оператора в сеансе пользователя 1С.

Готовая сборка лежит в общем макете ядра `ИИО_ТранспортMCP`, поэтому для установки ИИ-оператора Rust не нужен. Пересобирать компоненту нужно только при изменении этих исходников.

## Что умеет

- `initialize` с `instructions`, `ping`, `tools/list`, `tools/call`: ответ сразу или отложенный.
- Прогресс `notifications/progress` и отмена `notifications/cancelled`: отмена доходит до 1С.
- Сессии `Mcp-Session-Id`, ревизии протокола 2024-11-05, 2025-03-26 и 2025-06-18.
- Ответ на вызов приходит потоком SSE. Пока 1С думает, сервер раз в 20 с шлёт комментарий-keepalive, иначе клиенты на Node обрывают соединение через 300 с.

Ресурсы, промпты и задачи MCP пока не реализованы: ядру они не нужны. Интерфейс компоненты оставляет место, чтобы добавить их без поломки (`kind` в `ВзятьВызов`, реестры задаются целиком).

## Безопасность

- Сервер слушает только `127.0.0.1`.
- Запрос без токена или с неверным токеном получает `401` и до 1С не доходит. Токены сравниваются за постоянное время.
- Запросы с чужим `Origin` или `Host` получают `403`: так сервер защищён от DNS rebinding.
- Тело запроса — не больше 4 МБ.
- Без токена сервер не запускается. Токен ищется по порядку:
  1. переменная `WEB_TRANSPORT_MCP_TOKEN`;
  2. файл из переменной `WEB_TRANSPORT_MCP_TOKEN_FILE`;
  3. файл `%LOCALAPPDATA%\WebTransport\mcp-token` — его создаёт `tools/new-mcp-token.ps1`.
- Лог компоненты пишется в `%LOCALAPPDATA%\AiOperator\mcp-transport.log`. В него попадают только метод, код ответа и длительность. Аргументы и ответы инструментов не пишутся, потому что в них персональные данные.

## Интерфейс для 1С

Объект создаётся так: `Новый("AddIn.AiOperatorMcp.Transport")`. Источник внешних событий — `AiOperatorMcp`. Ядро вызывает методы только асинхронно (`…Асинх`).

| Метод | Что делает |
|---|---|
| `Запустить(Порт, Origins, ТаймаутСек)` | Запускает сервер. Возвращает JSON `{ok, code, error}`; коды ошибок: `NO_TOKEN`, `PORT_BUSY` и другие |
| `Остановить()` | Останавливает сервер. Ждущие вызовы получают ошибку |
| `УстановитьИнформациюОСервере(JSON)` | Задаёт `name`, `title`, `version`, `description`, `instructions` |
| `УстановитьИнструменты(JSON)` | Задаёт массив `{name, description, inputSchema}`. Компонента отдаёт его клиенту без изменений |
| `ВзятьВызов(Номер)` | Возвращает данные вызова `{kind, name, arguments, progressToken}`. Пустая строка — вызова уже нет |
| `ОтправитьОтвет(Номер, Текст)` | Успешный ответ. `Ложь` — вызов отменён, истёк или уже завершён |
| `ОтправитьОшибку(Номер, Код, Сообщение)` | Ошибка JSON-RPC |
| `УведомитьОПрогрессе(Номер, Прогресс, Всего, Сообщение)` | Прогресс. Отправляется, только если клиент передал `progressToken`; значения должны расти |
| `Состояние()` | JSON: работает ли сервер, порт, источник токена, число сессий и ждущих вызовов |

Внешние события:
- `TOOL_CALL {"callId"}` — пришёл новый вызов;
- `CANCELLED {"callId", "reason"}` — вызов отменён; `reason` равен `client` (отменил клиент) или `timeout` (истёк таймаут сервера).

## Сборка и проверка

```powershell
./tools/build-transport.ps1           # DLL x64 и x86, zip с манифестом, макет ядра, SHA256SUMS
./tools/build-transport.ps1 -Verify   # две чистые сборки должны совпасть побайтно и с SHA256SUMS
```

Что нужно для сборки:
- Rust 1.98.1 с тулчейнами `stable-x86_64-pc-windows-gnu` и `stable-i686-pc-windows-gnu`;
- `dlltool` из WinLibs (`winget install BrechtSanders.WinLibs.POSIX.MSVCRT`); gcc из WinLibs в `PATH` скрипт убирает сам, иначе ломается сборка x86.

Тесты не требуют 1С:

```powershell
cargo test --target x86_64-pc-windows-gnu
```

Вместо 1С в них подставные обработчики (`src/fake.rs`). Отладочный сервер `mcp-transport-dev` работает на той же библиотеке. Ключ `--snapshot build/mcp-full-acc.json` отдаёт инструменты и `instructions` из снимка: так проверяется, что компонента передаёт модели ровно то, что прислало ядро.

## Лицензии

Компонента распространяется под AGPL-3.0, как и ядро. Код написан с нуля по спецификации MCP (modelcontextprotocol.io) и документации Native API. Код прежней компоненты web-transport-addin, у которой нет лицензии, не использовался.

Зависимости — только с разрешительными лицензиями: MIT, Apache-2.0, BSD-3-Clause, Zlib, Unicode-3.0, Unlicense. `build-transport.ps1` проверяет список при каждой сборке. Основные:
- `addin1c` (MIT) — обёртка Native API;
- `hyper`, `hyper-util`, `http-body-util`, `tokio`, `bytes` (MIT) — HTTP-сервер;
- `serde_json`, `getrandom` (MIT/Apache-2.0);
- `subtle` (BSD-3-Clause) — сравнение за постоянное время.
