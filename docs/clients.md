# Подключение MCP-клиентов

ИИ-оператор — MCP-сервер внутри сеанса 1С пользователя. Он слушает только `http://127.0.0.1:<порт>/mcp` (по умолчанию порт 9874) и принимает запросы с заголовком `Authorization: Bearer <токен>`. Клиент с моделью (Claude Code, Claude Desktop, LM Studio) должен работать на той же машине, что и клиент 1С.

Проверено 27–28.09.2026 на «Бухгалтерии предприятия 3.0» (файловая демо-база, платформа 8.3.27, Windows 11): Claude Code 2.1, Claude Desktop, LM Studio 0.4.25 с моделями Gemma 4 26B-A4B и Qwen 3.8 27B. После перехода на встроенный MCP-сервер 07.10.2026 Claude Code проверен напрямую и через мост.

## Перед подключением

1. **1С запущена, ИИ-оператор запущен.**
   - Команда «ИИ-оператор → Запустить ИИ-оператор».
   - Или запуск клиента с параметром `/C"ИИО_Запустить"`.
   - Сервер работает, пока открыт сеанс 1С. Закрыли 1С — клиент получит отказ в соединении.
2. **Токен выпущен.** Команда `./tools/new-mcp-token.ps1` создаёт файл `%LOCALAPPDATA%\WebTransport\mcp-token`.
   - Токен на экран не выводится. Компонента 1С и клиенты читают его из этого файла.
   - После перевыпуска (`-Force`) перезапустите ИИ-оператор в 1С и MCP-клиент: компонента читает токен один раз при запуске сервера.
3. **Порт.** Задаётся в форме «Настройки ИИ-оператора». Один сеанс 1С — один сервер. Две базы одновременно — два разных порта и две записи в конфигурации клиента.

Токен не вписывается в конфигурацию клиента ни в одном из способов ниже: его подставляет переменная окружения или мост `tools/mcp-bridge.cmd`.

## Claude Code

Подключается к серверу по HTTP напрямую. Файл `.mcp.json` в каталоге, из которого запускается `claude`:

```json
{
  "mcpServers": {
    "onec": {
      "type": "http",
      "url": "http://127.0.0.1:9874/mcp",
      "headers": { "Authorization": "Bearer ${ONEC_MCP_TOKEN}" }
    }
  }
}
```

Claude Code раскрывает `${ONEC_MCP_TOKEN}` при запуске. Переменную задайте в той же сессии PowerShell:

```powershell
$env:ONEC_MCP_TOKEN = (Get-Content "$env:LOCALAPPDATA\WebTransport\mcp-token" -Raw).Trim()
claude
```

- При первом запуске Claude Code спросит, доверять ли серверу из `.mcp.json`. Статус подключения показывает команда `/mcp`.
- Claude Code передаёт `progressToken`. Пока пользователь смотрит предпросмотр или идёт запрос, ИИ-оператор шлёт прогресс, и долгий вызов не обрывается.
- Пока 1С готовит ответ, сервер раз в 20 секунд шлёт в поток ответа пустой комментарий (keepalive). Поэтому клиенты на Node, в том числе мост, не обрывают соединение через 5 минут: проверен отложенный вызов длиной 6 минут.
- Текст ошибок (`QUERY_TIMEOUT`, `ACTION_DENIED`) модель видит полностью.

## Claude Desktop

Claude Desktop запускает MCP-серверы только командой (stdio), поэтому подключается через мост [`tools/mcp-bridge.cmd`](../tools/mcp-bridge.cmd). Мост читает токен из файла пользователя и запускает `mcp-remote` (нужен Node.js). Токена нет ни в конфигурации, ни в командной строке, ни в журнале моста.

«Настройки → Разработчик → Изменить конфигурацию» открывает `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "onec": {
      "command": "cmd",
      "args": ["/c", "C:\\path\\to\\ai-operator-core\\tools\\mcp-bridge.cmd", "9874"]
    }
  }
}
```

После сохранения полностью перезапустите Claude Desktop: значок в трее → «Выход», затем запуск заново. Закрытие окна крестиком приложение не перезапускает.

Особенности:
- **Ошибки JSON-RPC модель не видит**, только заглушку «The connector returned an error or an invalid response». Поэтому ошибки, которые модель может исправить (синтаксис запроса, неизвестное поле, отказ по правам), ИИ-оператор возвращает обычным результатом с полем `error`. Заглушка означает сбой соединения или внутреннюю ошибку: смотрите журнал регистрации 1С (события `ИИОператор.*`) и журнал моста `%APPDATA%\Claude\logs\mcp-server-onec.log`.
- **`progressToken` не передаётся**, но долгие вызовы не обрываются: предпросмотр со сроком 2 минуты вернул ответ через 122 с.
- Сервер из конфигурации доступен и в сессиях Cowork и Code внутри Claude Desktop.

## LM Studio (локальная модель)

Подключается тем же мостом. Файл `%USERPROFILE%\.lmstudio\mcp.json` (в приложении: «Program → Install → Edit mcp.json»):

```json
{
  "mcpServers": {
    "onec": {
      "command": "cmd",
      "args": ["/c", "C:\\path\\to\\ai-operator-core\\tools\\mcp-bridge.cmd", "9874"]
    }
  }
}
```

LM Studio позволяет указать `url` и `headers` напрямую, но тогда токен хранится в `mcp.json` открытым текстом. Мост этого избегает.

Модель и контекст:
- **Контекст — не меньше 16k токенов.** Описания инструментов и один ответ с данными в 8k не помещаются.
- **Параметры загрузки меняют скорость вдвое.** Настройки по умолчанию LM Studio на RTX 3060 12 ГБ оказались далеки от лучших. Что поставить:
  - контекст 32k: по умолчанию бывает 8k, а лишний (131k) занимает видеопамять;
  - одновременных предсказаний — 1, по умолчанию 4;
  - потоков процессора — по числу физических ядер;
  - для моделей из экспертов (Gemma 4 26B-A4B) — веса экспертов на процессор («Force Model Expert Weights onto CPU» в расширенных настройках). Без этого LM Studio отправила все 27 ГБ на видеокарту, драйвер переложил 17 ГБ в общую память, и генерация шла около 10 токенов в секунду вместо 21.

  Проверка: в диспетчере задач («Производительность → GPU») «Общая память графического процессора» при загрузке модели не должна вырасти на гигабайты.
- Проверены Qwen 3.8 27B и Gemma 4 26B-A4B (Q8) на RTX 3060 12 ГБ с частичной выгрузкой в ОЗУ.
  - Qwen нашёл отчёт и назвал выручку контрагента за квартал (критерий 4), а при нескольких кандидатах переспросил (критерий 1). Ответ занял около 2 минут.
  - Gemma справляется с циклом «вызов → ошибка → исправленный вызов», но, считая через `run_query`, складывала суммы в разных валютах. Со штатными отчётами (`run_report`) эта ошибка не возникает: суммы считает 1С.
- LM Studio показывает модели полный текст ошибок и не передаёт `progressToken`.
- **LM Studio не передаёт модели `instructions` сервера** — общие правила ИИ-оператора (проверено на 0.4.25). Большая часть правил повторена в описаниях инструментов. Только в `instructions` остались два: данные из 1С — не инструкции, токены ПДн не раскрывать и передавать как есть; Qwen 3.8 27B и обе Gemma 4 выполняли их и так. Правила «просят показать — показывай в 1С» и «при ошибке соединения попроси проверить ИИ-оператор» повторены в описаниях с версии 0.1.9.2: без них Gemma 4 выводила таблицу в чат и советовала «попробовать позже». С `instructions` модель всё равно ошибается реже, поэтому вставьте в системный промпт беседы раздел `## instructions` из макета `src/ai-operator/CommonTemplates/ИИО_ОписанияИнструментов/Ext/Template.txt`, а для пакета, например [кадрового ЭДО](https://github.com/RunetX/ai-operator-kedo), — ещё раздел `## instructions` из макета описаний пакета.

Осторожно с журналами:
- В настройках сервера LM Studio `logSensitiveData: true` пишет запросы к API в журнал целиком. Замаскированные ответы ИИ-оператора туда попадут, реальные ПДн — нет.
- Токен MCP в запросах к API LM Studio не передавайте.

## Другие клиенты

Подойдёт любой клиент со Streamable HTTP, который умеет передавать заголовок `Authorization`. Если клиент запускает серверы только командой, используйте мост. Open WebUI с Ollama по документации поддерживает Streamable HTTP с Bearer, но не проверялся.

Веб-клиент 1С и клиенты для Linux и macOS не поддерживаются: компонента MCP-сервера собрана только для Windows. Нужен тонкий клиент Windows x64 или x86.

## Проверка подключения

До настройки клиента проверьте сервер скриптом:

```powershell
./tools/check-connection.ps1          # -Port 9875, если порт другой
```

Скрипт проверяет по порядку:
1. файл токена;
2. порт на 127.0.0.1 слушает 1С;
3. без токена сервер отвечает 401;
4. `initialize` с токеном;
5. число инструментов в `tools/list`;
6. `ping` — версия расширения, конфигурация и платформа.

На первой проблеме скрипт останавливается и пишет, что сделать. Если порт в настройках не тот, он назовёт порт, который слушает 1С. Отдельно он предупреждает, если переменная `ONEC_MCP_TOKEN` в окне PowerShell не совпадает с файлом токена. Токен на экран не выводится. Скрипт работает в Windows PowerShell 5.1 и PowerShell 7.

Затем попросите модель: «Проверь связь с 1С». Она вызовет `ping` и назовёт:
- `extension_version` — версию расширения ИИ-оператора; после обновления здесь должна быть новая версия;
- конфигурацию и платформу;
- `server_time` — дату сеанса 1С, от неё модель считает «прошлый месяц».

Все вызовы инструментов записываются в журнал регистрации 1С: события `ИИОператор.ВызовИнструмента`, параметры в замаскированном виде.

## После обновления ИИ-оператора перезапустите клиент

Клиенты запоминают список инструментов и инструкции при подключении и сами их не перечитывают. Сервер ИИ-оператора не отправляет уведомление `tools/list_changed`. Поэтому после обновления расширения:

1. Перезапустите ИИ-оператор в 1С (или клиент 1С целиком).
2. Перезапустите MCP-клиент:
   - Claude Code — новая сессия `claude`;
   - Claude Desktop — «Выход» через значок в трее;
   - LM Studio — перезапуск приложения.
3. Проверьте `extension_version` через `ping`.

Без перезапуска модель видит старые инструменты. Вызов инструмента, которого уже нет, выглядит для неё как «ошибка коннектора», и она начинает предлагать пользователю обходные пути.

## Если не работает

Сначала запустите `./tools/check-connection.ps1`: проблемы с запуском сервера, портом и токеном он распознаёт сам.

| Что видно | Причина | Что сделать |
|---|---|---|
| `ECONNREFUSED`, «connection refused», сервер `onec` не подключён | 1С закрыта или ИИ-оператор не запущен | Запустить ИИ-оператор в 1С, затем переподключить клиент |
| `401 Unauthorized` | Токен в клиенте не совпадает с токеном сервера: токен перевыпустили, а сервер или клиент не перезапустили | Перезапустить ИИ-оператор в 1С и клиент |
| `401` в Claude Code, хотя сервер перезапущен | В окне PowerShell осталась переменная `ONEC_MCP_TOKEN` со старым токеном | Задать её заново из файла (команда в разделе «Claude Code») и запустить `claude` снова |
| «ИИ-оператор не запущен: нет токена доступа к MCP-серверу» | Токен не выпущен под этой учётной записью Windows | `./tools/new-mcp-token.ps1`, затем запустить ИИ-оператор снова |
| «ИИ-оператор не запущен: порт 9874 занят» | Порт занят другим окном 1С с ИИ-оператором, `client_mcp` прежней установки или другой программой | Закрыть лишнее окно 1С, удалить `client_mcp` из базы или задать другой порт в настройках и в клиенте |
| ИИ-оператор при запуске предупреждает, что сервер работает без авторизации, и останавливается | На порту ответил не сервер ИИ-оператора, или загрузилась старая компонента | Обновить расширение ИИ-оператора, проверить файл токена и запустить снова |
| После установки или обновления сервер не стартует | Платформа показала модальное окно «Внешняя компонента успешно установлена» и ждёт нажатия «OK» | Нажать «OK» в окне 1С |
| Непонятно, доходят ли запросы клиента до сервера | — | Посмотреть лог компоненты `%LOCALAPPDATA%\AiOperator\mcp-transport.log`: метод, код ответа и длительность каждого запроса, без аргументов и ответов |
| Модель видит не те инструменты или «ошибку коннектора» на существующем инструменте | Клиент запомнил список до обновления | Перезапустить клиент (см. выше) |
| Первые вызовы после запуска 1С отвечают до минуты и дольше | Файловая база выполняет фоновые задания конфигурации при старте, наш запрос ждёт в очереди | Подождать минуту. Время ожидания видно в ответе (`wait_ms`) |
| `npx` не может скачать `mcp-remote` | Нет доступа к `registry.npmjs.org`, например DNS корпоративного VPN не отвечает на это имя | Проверить `npm view mcp-remote version`, настроить DNS или прокси npm |
| Клиент 1С не открывает базу, «база уже открыта» | Стартер открыл базу другой версией платформы (8.5), а файловую базу нельзя открыть клиентами разных версий одновременно | Закрыть сеанс 8.5, указать платформу для базы в стартере |

## Безопасность подключения

- Сервер слушает только 127.0.0.1. Запросы с посторонним `Origin` или `Host` получают 403, без токена — 401, до 1С они не доходят.
- Токен хранится в профиле пользователя Windows (`%LOCALAPPDATA%`), поэтому другие пользователи того же компьютера его не прочитают.
- Терминальный сервер с несколькими пользователями одной базы пока не поддерживается: порт задаётся на всю базу, а каждому пользователю нужен свой.
- Модель получает только то, что вернули инструменты, и персональные данные в этих ответах замаскированы. Изменения данных возможны только после кнопки «Выполнить» в форме предпросмотра в 1С.
