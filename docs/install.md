# Развёртывание ИИ-оператора

Пошаговая инструкция для администратора 1С: как установить ИИ-оператор в файловую базу, выдать права, подготовить рабочие места пользователей и подключить бота в обсуждениях 1С. Короткая версия — раздел [«Установка»](../README.md#установка) в README, подключение моделей подробно описано в [clients.md](clients.md).

Проверено на Windows 11 и платформе 8.3.27 с файловыми демо-базами «Бухгалтерии предприятия 3.0» и «Зарплаты и управления персоналом 3.1».

## Что и куда ставится

| Что | Куда | Сколько раз |
|---|---|---|
| ИИ-оператор (расширение «ИИОператор») со своим MCP-сервером | Расширение в базе | В каждую базу |
| Токен | Файл в профиле Windows пользователя | На каждого пользователя |
| MCP-клиент: Claude Code, Claude Desktop или LM Studio | Компьютер пользователя | На каждого пользователя |
| Канал «бот в обсуждениях 1С»: патч конфигурации и расширение «ИИОператор_Бот» | Конфигурация и расширение в базе | В каждую базу, где нужен бот |
| Модель с OpenAI-совместимым API: LM Studio или облачный сервис | Сервер модели в сети компании или облако | Одна на базу |

MCP-сервер работает во внешней компоненте. Она уже лежит внутри расширения «ИИОператор» готовой сборкой для Windows x64 и x86 и попадает на компьютер пользователя из базы при первом запуске. Ничего собирать не нужно, отдельные расширения для MCP не нужны.

Порядок:
1. [Подготовить машину для установки](#1-сборочная-машина). Если ставите готовые `.cfe` из Releases, этот шаг не нужен.
2. [Установить расширение в базу](#2-установка-в-базу).
3. [Выдать права и разрешения в 1С](#3-права-и-разрешения).
4. [Подготовить рабочее место пользователя](#4-рабочее-место-пользователя).
5. [Проверить связь](#5-проверка).
6. По желанию — [бот в обсуждениях 1С](#6-бот-в-обсуждениях-1с): вопросы прямо в 1С, без MCP-клиента.

Дальше: [обновление](#обновление), [удаление](#удаление), [если не получается](#если-не-получается).

## 1. Сборочная машина

Нужна для установки из исходников скриптом `build.ps1`. Это может быть и рабочее место пользователя.

| Что | Зачем | Как установить |
|---|---|---|
| Windows 10 или 11 x64 | — | — |
| Платформа 1С 8.3.24 или новее, 64-битная | Скрипты загружают расширения в базу утилитой `ibcmd` | Скрипты ищут `C:\Program Files\1cv8\<версия>\bin\ibcmd.exe` |
| PowerShell 7 | Скрипты установки | `winget install Microsoft.PowerShell` |
| Git | Репозиторий | `winget install Git.Git` |

Если установлено несколько версий 8.3, скрипты берут самую новую, другую можно указать параметром `-Platform 8.3.24.1342`. Платформу 8.5 скрипты сами не выбирают: она может перевести файловую базу в свой формат.

После установки откройте новое окно PowerShell 7 (`pwsh`), иначе в нём не будет новых путей. Дальше все команды выполняются в PowerShell 7.

**Репозиторий:**

```powershell
git clone https://github.com/RunetX/ai-operator-core.git
cd ai-operator-core
```

Если вы скачали ZIP-архив, Windows пометит файлы как полученные из интернета, и PowerShell откажется их запускать. После распаковки снимите пометку: `Get-ChildItem -Recurse | Unblock-File`.

### Пересборка компоненты (необязательно)

Для установки и для правок кода 1С это не нужно. Rust понадобится, только если вы меняете саму компоненту MCP-сервера: исходники лежат в `addin/mcp-transport`.

```powershell
./tools/build-transport.ps1           # собрать компоненту и положить её в макет ядра
./tools/build-transport.ps1 -Verify   # две чистые сборки должны совпасть побайтно и с SHA256SUMS
```

- Нужны Rust 1.98.1 с тулчейнами `stable-x86_64-pc-windows-gnu` и `stable-i686-pc-windows-gnu` и `dlltool` из WinLibs: `winget install BrechtSanders.WinLibs.POSIX.MSVCRT`.
- `dlltool` скрипт находит в WinLibs сам, каталоги с `gcc.exe` на время сборки убирает из PATH.
- Скрипт проверяет лицензии зависимостей.

Подробнее — [addin/mcp-transport/README.md](../addin/mcp-transport/README.md).

## 2. Установка в базу

**Готовые `.cfe`.** Для «Бухгалтерии предприятия 3.0», «Зарплаты и управления персоналом 3.1» и «Управления торговлей 11.5» ядро и бот (для УТ) собраны в [Releases](https://github.com/RunetX/ai-operator-core/releases). Расширение заимствует справочники пользователей, а их идентификаторы в разных конфигурациях разные, поэтому берите файл своей конфигурации. Загрузка:
1. Конфигуратор → «Конфигурация → Расширения конфигурации» → «Добавить» → «Загрузить из файла».
2. Снимите у расширения флажки «Безопасный режим» и «Защита от опасных действий».

Для другой конфигурации — скрипт ниже: он подставит идентификаторы этой базы.

Перед установкой:
- **Закройте все сеансы базы**, в том числе конфигуратор: `ibcmd` нужен монопольный доступ.
- **Сделайте резервную копию.** Для файловой базы достаточно скопировать её каталог, пока база закрыта.
- **Подготовьте пользователя 1С с административными правами**, если в базе есть пользователи.

```powershell
./build.ps1 -InfoBase 'C:\Bases\Acc' -User 'Администратор' -Password '<пароль>'
```

| Параметр | Что это |
|---|---|
| `-InfoBase` | Каталог файловой базы |
| `-User`, `-Password` | Пользователь 1С с административными правами. Если в базе нет пользователей, не указывайте |
| `-Platform` | Версия платформы, например `8.3.24.1342`. По умолчанию — самая новая 8.3 |
| `-Bot` | Ещё канал «бот в обсуждениях 1С», см. [раздел 6](#6-бот-в-обсуждениях-1с) |
| `-Tests` | Ещё расширение тестов, см. [«Тесты»](../README.md#тесты) |

Что делает скрипт:
1. Копирует исходники ИИ-оператора в `build/` и приводит их к формату выгрузки конфигуратора.
2. Подставляет идентификаторы справочников «Пользователи» и «Группы пользователей» из этой базы: расширение их заимствует, а в разных конфигурациях идентификаторы разные.
3. Загружает расширение «ИИОператор» и обновляет конфигурацию базы.
4. Выключает у расширения безопасный режим и защиту от опасных действий.

Почему без безопасного режима: MCP-сервер работает во внешней компоненте, а журналу операций нужен привилегированный режим. В безопасном режиме ни то ни другое недоступно.

В конце скрипт пишет «Готово.». Для другой базы запустите его с другим `-InfoBase`.

Скрипт работает только с файловыми базами. Клиент-серверные базы пока не поддерживаются, см. [«Ограничения»](../README.md#ограничения).

## 3. Права и разрешения

Откройте базу в 1С под администратором.

### Роли

| Роль | Что даёт | Как попадает к пользователю |
|---|---|---|
| ИИ-оператор: базовые права | Доступа к агенту не даёт | БСП сама добавляет её в профили с базовыми правами |
| ИИ-оператор: полные права | Все права на объекты расширения | БСП сама добавляет её в профиль «Администратор» |
| Пользователь ИИ-оператора | Запуск и остановка агента, предпросмотр действий, журнал операций со своими пакетами | Администратор добавляет явно |
| Администратор ИИ-оператора | То же, плюс настройки, маскирование, разрешения действий и пакеты всех пользователей в журнале операций | Администратор добавляет явно |

Первые две роли технические, с ними ничего делать не нужно. Полноправный пользователь работает с агентом без дополнительных ролей.

Чтобы дать доступ к агенту другим пользователям:
1. «Администрирование → Настройки пользователей и прав → Профили групп доступа» → «Создать». Наименование, например, «Пользователь ИИ-оператора». На вкладке «Разрешенные действия (роли)» отметьте роль «Пользователь ИИ-оператора» и запишите профиль.
2. «Группы доступа» → «Создать». Профиль — созданный на шаге 1, участники — пользователи, которые будут работать с агентом.

Поставляемые профили, например «Бухгалтер», менять не нужно: роли пользователя складываются из всех его групп доступа. Для тех, кто будет настраивать ИИ-оператор, так же заведите профиль с ролью «Администратор ИИ-оператора».

### Разрешения действий

Агент читает данные и открывает формы с правами пользователя. Проводить документы и отменять проведение он может, только если администратор это разрешил:
1. «ИИ-оператор → Разрешения действий ИИ-оператора» → «Создать».
2. **Пользователь** — пользователь или группа пользователей, например «Все пользователи».
3. **Действие** — «Провести (post)» или «Отменить проведение (unpost)». Пакеты добавляют в этот список свои действия.
4. Флажок **«Разрешено»**.

Как читаются записи:
- Нет записи — действие запрещено, даже полноправному пользователю.
- Запись на самого пользователя важнее записей на его группы: так можно запретить действие одному человеку из разрешённой группы.
- Если записей на группы несколько, достаточно одной разрешающей.
- Кроме разрешения, у пользователя должно быть право платформы на документ: «Проведение» или «Отмена проведения».

### Журнал регистрации

Аудит действий пишется в журнал регистрации, поэтому без уровня «Информация» действия недоступны. При запуске ИИ-оператор предупредит об этом: «Действия ИИ-оператора недоступны». В демо-базах журнал бывает выключен. Уровень меняется в конфигураторе: «Администрирование → Настройка журнала регистрации», нужна регистрация ошибок, предупреждений и информации или всех событий.

### Настройки

«ИИ-оператор → Настройки ИИ-оператора», нужна роль администратора ИИ-оператора. Значение 0 означает значение по умолчанию.

| Настройка | По умолчанию | Что это |
|---|---|---|
| Порт MCP-сервера | 9874 | Порт на 127.0.0.1. Если на одном компьютере одновременно открыты две базы с ИИ-оператором, у каждой должен быть свой порт |
| Таймаут ответа сервера | 900 с | Сколько сервер ждёт ответ 1С на вызов инструмента |
| Таймаут запроса | 30 с | Сколько выполняется запрос модели до отмены |
| Лимит строк в ответе | 200 | Сколько строк данных уходит модели за один ответ |
| Срок ожидания подтверждения | 120 с | Сколько форма предпросмотра ждёт решения пользователя |
| Ожидание очереди фоновых заданий | 120 с | Сколько запрос модели ждёт старта, пока база занята своими фоновыми заданиями |
| Максимальная длина текста запроса | 20 000 символов | Более длинный запрос модели отклоняется |
| Срок хранения журнала обмена с моделью | 90 дней | Сколько хранится журнал «Что видела нейросеть»: ходы бота и вызовы инструментов в маскированном виде |

### Маскирование персональных данных

Преднастройка полей с ПДн есть для «Бухгалтерии предприятия 3.0» и «Зарплаты и управления персоналом 3.1». Пакеты добавляют свою преднастройку. В другой конфигурации до начала работы откройте «ИИ-оператор → Маскирование персональных данных» и добавьте объекты и поля с ПДн. Без этого от модели закрываются только значения, похожие на ИНН физлица, телефон, СНИЛС, паспорт и email.

Сверху той же формы («Что видит нейросеть») — состояние защиты, сводка журнала обмена за 30 дней и флажок **строгого режима**: он скрывает от модели и данные контрагентов-юрлиц (наименование, ИНН, КПП, контакты). Включайте его, если служба безопасности считает коммерческой тайной и названия контрагентов; сопоставлять контрагентов по ИНН модель при этом не сможет. Что именно ушло модели, видно в «ИИ-оператор → Журнал обмена с моделью».

## 4. Рабочее место пользователя

**Что нужно:**
- тонкий клиент 1С для Windows, x64 или x86. Веб-клиент и клиенты для Linux и macOS не подойдут: компонента собрана только для Windows;
- скрипты из папки `tools`: `new-mcp-token.ps1`, `check-connection.ps1` и `mcp-bridge.cmd`. Скопируйте папку или клонируйте репозиторий;
- MCP-клиент, а для Claude Desktop и LM Studio ещё Node.js: `winget install OpenJS.NodeJS.LTS`.

Rust, средства сборки и отдельные расширения на рабочем месте не нужны.

PowerShell 7 на рабочем месте не обязателен: `new-mcp-token.ps1` и `check-connection.ps1` работают и во встроенном Windows PowerShell 5.1. Но там запуск скриптов по умолчанию запрещён, поэтому запускайте их так:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\new-mcp-token.ps1
```

**Токен.** Выпускается под учётной записью Windows того пользователя, который работает в 1С:

```powershell
./tools/new-mcp-token.ps1
```

- Токен записывается в `%LOCALAPPDATA%\WebTransport\mcp-token` и на экран не выводится.
- У каждой учётной записи Windows свой токен, другие пользователи компьютера его не прочитают.
- Без токена сервер не запускается.
- Перевыпуск — `./tools/new-mcp-token.ps1 -Force`. После него перезапустите ИИ-оператор в 1С и MCP-клиент.

Вместо файла токен можно передать переменной окружения `WEB_TRANSPORT_MCP_TOKEN`, а путь к другому файлу — переменной `WEB_TRANSPORT_MCP_TOKEN_FILE`. Сервер ищет токен в таком порядке: переменная с токеном, переменная с путём к файлу, файл по умолчанию.

**Первый запуск.** Откройте базу и выполните команду «ИИ-оператор → Запустить ИИ-оператор».
- При первом запуске на компьютере платформа устанавливает компоненту и показывает окно «Внешняя компонента успешно установлена». Пока его не закрыть кнопкой «OK», сервер не стартует. Окно появится снова, только когда в новой версии ИИ-оператора изменится компонента.
- Перед стартом ИИ-оператор проверяет себя: отправляет серверу запрос без токена. Если ответ не 401, сервер останавливается, а пользователь видит причину.
- Когда всё в порядке, 1С показывает оповещение «ИИ-оператор запущен» с адресом сервера.

**Автозапуск.** В окне запуска 1С выделите базу → «Изменить» → на последней странице в поле «Дополнительные параметры запуска» впишите `/C"ИИО_Запустить"`. Если там уже есть параметр `/C`, добавьте значение через точку с запятой: `/C"ИИО_Запустить;<прежнее значение>"`.

**MCP-клиент.** Настройка Claude Code, Claude Desktop и LM Studio описана в [clients.md](clients.md). В конфигурации Claude Desktop и LM Studio укажите полный путь к `tools\mcp-bridge.cmd` на этом компьютере.

**Лог компоненты** — `%LOCALAPPDATA%\AiOperator\mcp-transport.log`. В нём только метод, код ответа и длительность каждого запроса. Аргументов и ответов инструментов там нет: в них могут быть персональные данные.

## 5. Проверка

1. 1С открыта, ИИ-оператор запущен.
2. Проверьте сервер скриптом:

   ```powershell
   ./tools/check-connection.ps1          # -Port 9875, если порт другой
   ```

   Скрипт проверяет файл токена, порт, ответ 401 без токена, подключение с токеном, список инструментов и `ping`. На первой проблеме он останавливается и пишет, что сделать.
3. В MCP-клиенте попросите: «Проверь связь с 1С». Модель вызовет `ping` и назовёт версию расширения, конфигурацию и платформу.
4. Попросите показать документы, например: «Покажи реализации за прошлый месяц». В 1С откроется список с отбором.
5. В журнале регистрации появятся события `ИИОператор.ВызовИнструмента`.

## 6. Бот в обсуждениях 1С

Второй канал ИИ-оператора: пользователь пишет боту «ИИ-оператор» в обсуждении документа или в личной переписке 1С, а ответ приходит туда же, с кнопками «Открыть» и «Предпросмотр». MCP-клиент и токен для этого не нужны: агентный цикл выполняется на сервере 1С, модель вызывается по HTTP.

Как это устроено:
- **Личный бот.** У каждого пользователя, которому доступен ИИ-оператор, свой экземпляр бота. Для людей он один — «ИИ-оператор», но отвечает только своему владельцу и работает с его ролями и ограничениями доступа. Чужому пользователю бот отказывает, модель при этом не вызывается.
- **Ход в фоновом задании.** Сообщения боту обрабатывает регламентное задание раз в 5 секунд, ход агента идёт в фоновом задании от имени владельца. Пока ответ готовится, в ветке висит «Думаю…», потом бот заменяет его ответом.
- **Изменения — только кнопкой.** Модель не меняет данные сама: под ответом появляется кнопка «Предпросмотр», в форме предпросмотра пользователь нажимает «Выполнить». После этого бот пишет итог в ветку.
- **Персональные данные.** Вопрос пользователя маскируется до отправки модели: людей из базы находят правила по справочникам, остальных — шаблоны и, если задана, локальная модель маскирования. Модель видит `[ФИО#1]`, человек в 1С — настоящие имена. Сам разговор хранится в сервисе взаимодействия 1С, как любая переписка в обсуждениях: модель ПДн не видит, но из 1С они уходят туда же, куда и остальные обсуждения. Если это важно, используйте собственный сервер взаимодействия.
- **Повтор при сбое модели.** Если модель ответила сбоем, который проходит сам (обрыв соединения, ошибка сервера, перезапуск движка LM Studio), ход повторяет запрос через 5, 10 и 15 секунд. Ошибку запроса бот сразу показывает понятным текстом.

### Что нужно

- Платформа 8.3.25 или новее и режим совместимости конфигурации не ниже 8.3.25: кнопки в сообщениях появились в 8.3.25.
- Конфигурацию можно менять: снятая с поддержки или на поддержке с разрешёнными изменениями. Боты до платформы 8.5.5 бывают только в конфигурации, поэтому нужен небольшой патч.
- База зарегистрирована в Системе взаимодействия (1С:Диалог или собственный сервер).
- Модель с OpenAI-совместимым API (`/v1/chat/completions`) и вызовом инструментов. Проверено на Gemma 4 26B-A4B в LM Studio с контекстом 32k: запрос агента занимает около 5 тыс. токенов.
- Расширение ИИ-оператора из [раздела 2](#2-установка-в-базу).

Проверено на «Управлении торговлей 11.5» с платформой 8.3.27.

### Установка

1. **Патч конфигурации.** Закройте все сеансы базы и сделайте резервную копию. Скрипт добавит в конфигурацию бота «ИИОператор» и пустой обработчик подбора пользователей, логики в них нет:

   ```powershell
   ./tools/install-bot-cfg.ps1 -InfoBase 'C:\Bases\Trade' -User 'Администратор'
   ./tools/install-bot-cfg.ps1 -InfoBase 'C:\Bases\Trade' -User 'Администратор' -Check   # на месте ли патч
   ```

   Для серверной базы — `-Server 'srv1c\trade'`, а начало сеансов на время обновления заблокируйте в консоли кластера. После обновления типовой конфигурации запустите скрипт снова. Подробнее о патче — [src/ai-operator-bot-cfg](../src/ai-operator-bot-cfg/README.md).
2. **Расширение «ИИОператор_Бот»** вместе с ядром:

   ```powershell
   ./build.ps1 -InfoBase 'C:\Bases\Trade' -User 'Администратор' -Bot
   ```

   Или загрузите в конфигураторе готовые `.cfe` ядра и бота для УТ из Releases, как в [разделе 2](#2-установка-в-базу).
3. **Регистрация в Системе взаимодействия.** В 1С под администратором: «Администрирование → Общие настройки → Обсуждения» → «Подключить». Если база уже зарегистрирована, ничего делать не нужно.
4. **Модель.** «ИИ-оператор → Настройки ИИ-оператора», группа «Модель»:

   | Настройка | Что указать |
   |---|---|
   | Адрес модели агента | Адрес API без `/chat/completions`, например `http://192.168.1.20:1234/v1` для LM Studio на компьютере в сети. Пусто — бот не подключён к модели |
   | Имя модели агента | Имя, как его показывает сервис, например `google/gemma-4-26b-a4b` |
   | Ключ API модели агента | Для облачных сервисов. Хранится в безопасном хранилище и в форме не показывается |
   | Таймаут ответа модели | Сколько ждать один ответ модели. По умолчанию 180 с |
   | Шагов агента за ход | Сколько раз за ход агент обращается к модели. По умолчанию 8 |
   | Сообщений истории | Сколько последних сообщений разговора видит модель. По умолчанию 20 |
   | Адрес и имя модели маскирования | Локальная модель, которая ищет в вопросе людей, которых нет в базе. Только `localhost` или частная сеть: ей уходит исходный текст. Пусто — таких людей ищут шаблоны |
   | Срок хранения диалогов | Сколько хранятся словарь маскирования и история разговора после последнего сообщения. По умолчанию 24 ч |

   Если в базе включены профили безопасности, при записи адреса БСП попросит разрешить обращение к нему.
5. **Личные боты.** Регламентное задание «Обслуживание канала ИИ-оператора» создаёт бота каждому пользователю с ролью «Пользователь ИИ-оператора» или «Администратор ИИ-оператора» либо с полными правами и выключает ботов тем, у кого доступ отобрали. Чтобы боты появились сразу, выполните задание вручную: «Администрирование → Обслуживание → Регламентные и фоновые задания».

В файловой базе регламентные задания выполняет открытый клиент 1С: бот отвечает, пока база где-нибудь открыта. Чтобы бот работал без открытого клиента, нужна клиент-серверная база.

### Проверка

1. Откройте документ, например реализацию, нажмите «Обсуждение» и напишите получателю «ИИ-оператор»: «Что с этим документом?».
2. Через несколько секунд в ветке появится «Думаю…», затем ответ. Если ответ упоминает объект, под ним будет кнопка «Открыть».
3. Начать разговор заново — сообщение «начать заново»: бот забудет историю в этом обсуждении.
4. В журнале регистрации появятся события `ИИОператор.ВызовМодели` с длительностью, шагами и токенами, без текстов.

## Обновление

```powershell
git pull
./build.ps1 -InfoBase 'C:\Bases\Acc' -User 'Администратор' -Password '<пароль>'
```

- Перед `build.ps1` закройте все сеансы базы.
- Если ставили готовые `.cfe`, загрузите новый файл из Releases в то же расширение «ИИОператор» в конфигураторе. Затем проверьте, что у расширения по-прежнему сняты флажки «Безопасный режим» и «Защита от опасных действий».
- Данные расширения сохраняются: настройки, разрешения, маскирование и данные отката.
- Если в базе стоит бот, добавьте к `build.ps1` ключ `-Bot`. После обновления типовой конфигурации снова запустите `./tools/install-bot-cfg.ps1`: обновление снимает патч.
- Если в новой версии изменилась компонента, при первом запуске у пользователей снова появится окно «Внешняя компонента успешно установлена». Его нужно закрыть кнопкой «OK».

После обновления на каждом рабочем месте перезапустите 1С и MCP-клиент: клиенты запоминают список инструментов при подключении (подробнее — в [clients.md](clients.md#после-обновления-ии-оператора-перезапустите-клиент)). Затем проверьте версию расширения через `ping`.

### Переход с client_mcp

До версии 0.1.13.0 включительно ИИ-оператору было нужно ещё расширение `client_mcp` с отдельно собранной компонентой. Теперь MCP-сервер встроен в расширение «ИИОператор». Порядок перехода:
1. Обновите расширение «ИИОператор» до новой версии, как описано выше.
2. Удалите расширение `client_mcp` в конфигураторе: «Конфигурация → Расширения конфигурации».
3. Токен и настройки MCP-клиентов менять не нужно: адрес прежний, `http://127.0.0.1:9874/mcp`, токен тот же.

Если `client_mcp` остался в базе, он не мешает. Исключение — его запускают параметром `/C"runMcp"` на том же порту: тогда ИИ-оператор сообщит, что порт занят.

**Откат.** Установите прежний релиз ядра 0.1.13.0 вместе с `client_mcp`, как было до перехода.

## Удаление

1. Закройте все сеансы базы.
2. В конфигураторе: «Конфигурация → Расширения конфигурации». Удалите сначала пакеты ИИ-оператора, если они есть, затем «ИИОператор_Бот» и «ИИОператор». Если от прежней установки остался `client_mcp`, удалите и его. Бот «ИИОператор» в конфигурации без расширения ничего не делает, удалить его можно в конфигураторе.
3. Вместе с расширением удаляются его данные: настройки, разрешения, маскирование и данные отката. События `ИИОператор.*` в журнале регистрации остаются.
4. На рабочих местах удалите файл `%LOCALAPPDATA%\WebTransport\mcp-token`, лог `%LOCALAPPDATA%\AiOperator\mcp-transport.log` и сервер `onec` из конфигурации MCP-клиента.

## Если не получается

| Что видно | Причина | Что сделать |
|---|---|---|
| `Не найдена платформа 8.3` | Платформа 32-битная или установлена не в `C:\Program Files\1cv8` | Установить 64-битную платформу или указать `-Platform` |
| `ibcmd ... завершился с кодом ...` | Чаще всего база открыта: сеанс 1С, конфигуратор или зависший процесс 1С | Закрыть все сеансы. Текст ошибки `ibcmd` — строками выше |
| `В конфигурации базы нет объекта Catalogs\Пользователи` | Конфигурация не на БСП | ИИ-оператору нужна конфигурация на БСП 3.1 |
| PowerShell: «выполнение сценариев отключено в этой системе» | Политика выполнения Windows PowerShell или пометка «из интернета» | Запускать в PowerShell 7 или с `-ExecutionPolicy Bypass`, для архива — `Unblock-File` |
| В 1С нет раздела «ИИ-оператор» или при запуске «У пользователя нет роли «Пользователь ИИ-оператора»» | Роль не выдана | См. [«Роли»](#роли) |
| «Действия ИИ-оператора недоступны» | Журнал регистрации не пишет уровень «Информация» | См. [«Журнал регистрации»](#журнал-регистрации) |
| Агент отвечает `ACTION_DENIED` | Нет разрешения на действие или права платформы | См. [«Разрешения действий»](#разрешения-действий) |
| «ИИ-оператор не запущен: нет токена доступа к MCP-серверу» | Токен не выпущен под этой учётной записью Windows, файл пуст или переменная указывает на несуществующий файл | Выпустить токен ([раздел 4](#4-рабочее-место-пользователя)) и запустить ИИ-оператор снова |
| «ИИ-оператор не запущен: порт 9874 занят» | Порт занят другим окном 1С с ИИ-оператором, `client_mcp` прежней установки или другой программой | Закрыть лишнее окно 1С, удалить `client_mcp` ([«Переход с client_mcp»](#переход-с-client_mcp)) или задать другой порт в настройках |
| «ИИ-оператор остановлен: MCP-сервер принимал запросы без токена авторизации» | На порту ответил не сервер ИИ-оператора, или загрузилась старая компонента | Обновить расширение «ИИОператор», проверить файл токена и запустить снова |
| Сервер не стартует после установки или обновления | Платформа ждёт «OK» в окне «Внешняя компонента успешно установлена» | Нажать «OK» в окне 1С |
| Запросы клиента получают 403 | В запросе чужой `Origin` или `Host`: так сервер отсекает обращения со сторонних веб-страниц | Подключать клиент напрямую по адресу `http://127.0.0.1:<порт>/mcp`, как в [clients.md](clients.md) |
| `install-bot-cfg.ps1`: конфигуратор завершился с ошибкой при загрузке патча | Конфигурация на поддержке без разрешения изменений или открыта в другом сеансе | Разрешить изменения в настройках поддержки, закрыть сеансы |
| В списке получателей обсуждения нет «ИИ-оператор» | База не зарегистрирована в Системе взаимодействия, у пользователя нет роли или задание обслуживания ещё не выполнялось | См. [раздел 6](#6-бот-в-обсуждениях-1с), шаги 3 и 5 |
| Бот молчит | Файловая база нигде не открыта, или выключено регламентное задание «Обработка сообщений ботам ИИ-оператора» | Открыть базу или включить задание |
| «ИИ-оператор не подключен к модели» | Пустой адрес или имя модели | Заполнить группу «Модель» в настройках |
| «Модель сейчас недоступна» | Сервис модели не отвечает: выключен, другой адрес или порт закрыт | Проверить адрес в настройках и доступ к нему с сервера 1С |
| «Модель вернула ошибку…» | Сервис модели ответил ошибкой, повторы не помогли | Текст ошибки — в журнале регистрации, событие `ИИОператор.ВызовМодели` |

Сбои запуска сервера пишутся в журнал регистрации, события `ИИОператор.*`. Что приходило на сервер и с каким кодом он ответил, видно в логе компоненты `%LOCALAPPDATA%\AiOperator\mcp-transport.log`.

Проблемы подключения клиента (`401`, отказ в соединении, старый список инструментов) разобраны в [clients.md](clients.md#если-не-работает).
